# T2 data card and implementation

This is an author document. It must not be copied into the research image. The agent-facing contract is `prompts/ode/common.md` and exposes only a two-dimensional autonomous cubic polynomial problem.

The private generator uses `z1'=z2`, `z2'=-a*z1-b*z2-c*z1^3-d*z1^2*z2`, with independent uniform a in [0.6,1.4], b in [0.15,0.4], c in [0.2,0.8]. Easy/medium have d=0; hard has d uniform in [0.1,0.4]. This family, support and coefficients are not agent inputs. Parameters are sampled once; no solver performance is used to accept or reject systems.

Each case supplies six training and two independent noisy validation trajectories at 301 times over [0,6], exact initial states, the public monomial dictionary, and actual per-trajectory/channel standard deviations. Noise is independent at all observations, including the observation at time zero. Relative clean-RMS noise is 0.005, 0.015 or 0.03 by level. Private files preserve clean states, true derivatives at those states, noise realizations, noise scales, energy, hidden trajectories and a 21 by 21 vector-field grid. All arrays are binary64 without pickle.

Ground truth is integrated from the analytic RHS with DOP853 (rtol 1e-12, atol 1e-14). One training and one hidden trajectory per system are independently integrated using Radau (1e-11, 1e-13); relative discrepancy must be below 1e-8. The coefficient-library RHS is checked against the separate analytic implementation, and energy derivative identity and monotonicity are checked across all clean trajectories. Rank, singular values, condition number and state coverage are recorded; high condition numbers do not cause resampling. The field grid is a scoring domain, not a trajectory constraint. Energy is coercive and nonincreasing, which bounds trajectories but does not restrict them to this square.

The scorer verifies private file hashes, array shapes, finite values, time grid, initial states, and coefficient/field consistency before considering a candidate. GT corruption raises a trusted-evaluation error. Candidate parsing requires exactly one coefficients key, finite numeric shape (10,2), and no duplicate keys. Absolute values below 1e-6 are zeroed. K > 10 scores zero. Each hidden integration is a separate reaped subprocess with a five-second deadline; finite coefficients that overflow or produce failed integration are valid artifacts with scientific failure and zero score. They are not discarded from first-valid tracking. Successful cases are scored using maximum relative hidden-rollout error and relative field error; both gates are <=0.05.

The standalone baseline supports `--method raw`, `fixed` and `search`. `raw` is unsmoothed numerical differences with dense least squares. `fixed` uses SG31/poly3/trim15 and STLSQ threshold0.02 for eight rounds. `search` selects among SG windows 11/21/31 and thresholds 0/0.02/0.05/0.1 using only public noisy-validation error plus 1e-4*K, rejects K>10, and falls back to fixed if all candidates fail. These are three distinct methods. Their results, including failures, must be retained by the common runner.

Actual generation, calibration, Linux isolation, model runs, and freeze status are established by the root execution records, not by this implementation description. This file does not claim those checks have already passed.
